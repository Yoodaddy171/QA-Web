QA Desk Guide

DevLog Automation Capture

Panduan singkat untuk menghubungkan automation Katalon ke DevLog, menangkap execution log, console, network, lalu meninjau hasilnya dari detail test case.

Aplikasi QA Desk / Web QA
Relay http://127.0.0.1:3001
Target User QA Engineer
i

Konsep singkat

DevLog adalah tempat review hasil testing. Automation mengirim log ke relay lokal, relay menyimpan data berdasarkan UUID test case, lalu QA Desk menampilkan hasilnya pada tab DevLog di detail test case.

Persiapan

Komponen Yang perlu dipastikan
QA Desk Website berjalan di localhost dan project/test case yang ingin dites sudah tersedia.
Relay DevLog Jalankan relay dengan node mini-services/ws-server.js atau gunakan run-web-qa.bat agar web dan relay berjalan bersamaan.
Test Case UUID Buka detail test case, bagian Informasi Utama, lalu salin Internal Database ID (UUID). ID ini berbeda dari display ID seperti E-124.
Katalon Script Script harus memiliki konfigurasi UUID test case, helper pengiriman log ke relay, dan inisialisasi DevTools/CDP. Contoh lengkap struktur script tersedia pada bagian Detail Setup di dokumen ini.
DevTools Library Pastikan Katalon memiliki Selenium DevTools library yang sesuai dengan versi browser. Contoh project ini memakai jar Drivers/selenium-devtools-v138-4.36.0.jar dan classpath Katalon juga dapat memuat selenium-devtools-v143.
Desired Capabilities Aktifkan logging browser/performance pada browser yang dipakai automation, terutama untuk fallback console/network log.

Alur Automation Capture

1

Jalankan QA Desk dan relay

Buka terminal dari folder Web QA, lalu jalankan launcher atau relay manual.

run-web-qa.bat atau node mini-services/ws-server.js
2

Ambil UUID test case

Buka test case yang akan dites, pilih tab Informasi Utama, lalu copy Internal Database ID.

Gunakan UUID ini pada script Katalon agar log masuk ke test case yang benar.

3

Siapkan script Katalon

Tambahkan import, config, helper logging, dan init DevTools/CDP seperti contoh lengkap di bawah. Jika sudah punya script lama, sisipkan bagian DevLog ini tanpa mengubah flow test utama.

4

Jalankan automation

Run script dari Katalon. Selama relay live, log execution, console, dan network akan dikirim ke DevLog.

Jika log tidak muncul, cek lagi status relay dan UUID test case.

Detail Setup Katalon untuk DevLog

!

Yang akan ditambahkan ke script

Agar DevLog bekerja, script Katalon perlu mengirim structured log ke relay lokal dan, jika ingin network/console browser tertangkap otomatis, perlu membuka Selenium DevTools/CDP session. Bagian di bawah menjelaskan setup minimal yang bisa ditempel ke script automation baru atau script existing.

0

Install/aktifkan Selenium DevTools library

Fitur auto-sniffer Network dan Console memakai Selenium CDP. Jika library DevTools tidak cocok dengan versi browser, initDevTools() bisa gagal dan Network otomatis tidak lengkap.

  • Cek versi browser automation yang dipakai, misalnya Edge/Chrome major version.
  • Pastikan Katalon memiliki jar selenium-devtools-v<versi> yang mendekati versi browser.
  • Jika belum ada, tambahkan jar ke folder Drivers project Katalon atau gunakan DevTools jar terbaru dari paket Katalon/Selenium yang tersedia.
  • Contoh project ini memiliki Drivers/selenium-devtools-v138-4.36.0.jar dan classpath juga memuat org.seleniumhq.selenium.selenium-devtools-v143_4.39.0.jar.
1

Set Desired Capabilities browser

Untuk Edge Chromium, setting project yang sudah dipakai ada di settings/internal/com.kms.katalon.core.webui.edge chromium.properties.

{ "EDGE_CHROMIUM_DRIVER": { "goog:loggingPrefs": { "browser": "ALL", "performance": "ALL" }, "ms:edgeOptions": { "args": ["--disable-notifications"] } } }

Jika memakai Chrome, isi Chrome Desired Capabilities dengan konsep yang sama. Di Katalon biasanya bisa diatur dari Project > Settings > Desired Capabilities > Web UI > Chrome, atau lewat file settings/internal/com.kms.katalon.core.webui.chrome.properties.

{ "CHROME_DRIVER": { "goog:loggingPrefs": { "browser": "ALL", "performance": "ALL" }, "goog:chromeOptions": { "args": ["--disable-notifications"] } } }

Catatan: Chrome tetap membutuhkan Selenium DevTools jar yang cocok dengan versi Chrome. Jika initDevTools() gagal, fallback console log masih bisa berjalan, tetapi auto network capture dari browser bisa tidak lengkap.

2

Tambahkan import library di bagian paling atas script

Import pertama dipakai untuk structured log ke relay. Import DevTools dipakai agar browser network dan console bisa ditangkap otomatis.

import groovy.transform.Field import groovy.json.JsonOutput import org.apache.http.entity.StringEntity import org.apache.http.client.config.RequestConfig import org.apache.http.client.methods.HttpPost import org.apache.http.impl.client.CloseableHttpClient import org.apache.http.impl.client.HttpClients import org.openqa.selenium.logging.LogEntry import org.openqa.selenium.logging.LogType import com.kms.katalon.core.webui.driver.DriverFactory import org.openqa.selenium.devtools.DevTools import org.openqa.selenium.devtools.HasDevTools import java.util.Optional import java.util.function.Consumer
3

Tambahkan konfigurasi relay dan UUID test case

Ganti <UUID_TEST_CASE> dengan Internal Database ID dari detail test case di QA Desk. Jangan memakai display ID seperti E-124.

@Field String webQaTestCaseId = "<UUID_TEST_CASE>" @Field String RELAY_URL = "http://127.0.0.1:3001/log"
4

Copy helper structured log dari contoh script

Tambahkan helper bernama sendStructuredLog. Helper ini mengirim tiga kategori log: execution untuk langkah test, console untuk browser log, dan network untuk request API.

def sendStructuredLog(String category, Map data) { try { Map payload switch (category) { case 'console': payload = [ type : 'log', testCaseId: webQaTestCaseId, level : data.level ?: 'INFO', log : data.message ?: '' ] break case 'network': payload = [ type : 'log', testCaseId: webQaTestCaseId, network : data, log : 'Network Trace' ] break case 'execution': default: payload = [ type : 'log', testCaseId: webQaTestCaseId, log : data.message ?: '' ] break } RequestConfig config = RequestConfig.custom() .setConnectTimeout(1000) .setSocketTimeout(1000) .setConnectionRequestTimeout(1000) .build() HttpPost post = new HttpPost(RELAY_URL) post.setHeader("Content-Type", "application/json") post.setEntity(new StringEntity(JsonOutput.toJson(payload), "UTF-8")) CloseableHttpClient client = HttpClients.custom() .setDefaultRequestConfig(config) .build() client.execute(post).close() client.close() } catch (Exception ignored) { // DevLog tidak boleh membuat automation gagal. } }
5

Gunakan helper sesuai jenis log

Buat wrapper sederhana agar setiap step penting otomatis masuk ke DevLog. Browser network dan console ditangkap otomatis setelah initDevTools() berhasil dipanggil.

def writeLog(String message) { WebUI.comment(message) sendStructuredLog('execution', [message: message]) maybeSniffLogs() } def logNetworkCall(String method, String url, def resp) { sendStructuredLog('network', [ method : method.toUpperCase(), url : url, status : resp?.statusCode ?: 0, success: resp?.success ?: false, data : resp?.responseText ?: '' ]) } // Panggil setelah browser dibuka agar Network dan Console otomatis tertangkap. initDevTools()
6

Tambahkan initDevTools untuk auto capture browser

Bagian ini membuka CDP session. Setelah aktif, script bisa menangkap browser console dan network tanpa menulis log manual untuk setiap request. Implementasi detail bisa berbeda antar versi Selenium, jadi mulai dari pola ini lalu sesuaikan versi DevTools jar yang tersedia.

def initDevTools() { try { def driver = DriverFactory.getWebDriver() if (!(driver instanceof HasDevTools)) { writeLog("Browser driver does not support DevTools.") return } devTools = ((HasDevTools) driver).getDevTools() devTools.createSession() // Enable Network dan Console domain sesuai versi selenium-devtools. // Jika versi browser berbeda, sesuaikan import/class DevTools jar. writeLog("DevTools session started.") } catch (Exception e) { writeLog("DevTools init failed: " + e.message) } }

Jika initDevTools() gagal, execution log tetap masuk, tetapi auto network/console bisa berkurang. Untuk request dari helper/API JVM, tetap kirim manual lewat logNetworkCall.

Cara Review Hasil di DevLog

Tab Fungsi
Execution Melihat langkah utama automation, termasuk step yang sukses, warning, atau gagal.
Console Melihat error atau warning browser yang terjadi selama testing.
Network Melihat request API yang relevan, status code, payload, header, dan response.
Current Kembali ke run terbaru setelah membuka history/previous run.
Previous Membuka run sebelumnya. History disimpan ringkas agar tidak memenuhi storage.
AI Summary Membuat ringkasan hasil test berdasarkan log terbaru, bukan dari history.

Checklist Sebelum Run

  • QA Desk terbuka di project yang benar.
  • Relay menunjukkan status live.
  • UUID test case sudah sesuai dengan test case yang akan dijalankan.
  • Script Katalon memakai endpoint relay http://127.0.0.1:3001/log.
  • Setelah automation selesai, buka detail test case dan cek tab DevLog.

Troubleshooting Cepat

Masalah Yang dicek
Relay belum live Pastikan mini-service berjalan dan port 3001 tidak dipakai proses lain.
Log tidak masuk Cek UUID test case, URL relay, dan apakah script benar-benar memanggil fungsi pengiriman log.
Network terlalu sedikit Pastikan CDP/devtools sniffer aktif. Request dari helper JVM tidak selalu tertangkap oleh browser CDP, jadi perlu dikirim manual sebagai structured log.
AI Summary terasa salah Pastikan sedang melihat Current run, bukan Previous. Summary seharusnya memakai hasil test terbaru.
