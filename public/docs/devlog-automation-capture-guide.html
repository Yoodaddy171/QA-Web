1. Overview

Automation Capture membantu tim melihat apa yang terjadi selama pengujian, bukan hanya status lulus atau gagal. Devlog menampilkan execution step, browser console, network activity, screenshot, evidence, dan history pada test case QA-Web yang tepat.

Dua mode, satu pipeline. Manual Capture memakai browser yang dikontrol relay. Katalon Capture memakai browser Selenium yang dikontrol Katalon. Keduanya baru menyatu setelah event dinormalisasi.

Evidence adalah artefak pendukung seperti screenshot atau recording. History adalah hasil run sebelumnya yang disimpan relay untuk membantu perbandingan.

3. Architecture

Manual Capture

User starts Manual Capture
    -> relay opens browser
    -> CDP captures browser events
    -> relay normalizes events
    -> WebSocket broadcasts events
    -> Devlog displays logs

Katalon Capture

Katalon runs test case
    -> DevLogListener starts run
    -> DevLog.groovy captures steps, network, and console
    -> events are normalized
    -> relay receives events through /log
    -> WebSocket broadcasts events
    -> Devlog displays logs

4. Manual Capture Guide

  1. Generate token dengan npm run relay:token, salin nilainya ke .env, lalu jalankan npm run dev dan npm run relay.
  2. Buka detail test case yang ingin diuji, lalu buka tab Devlog.
  3. Pastikan status relay aktif. Buka bagian Manual Capture.
  4. Masukkan URL target, pilih browser atau mode recording bila tersedia, lalu klik Start Capture.
  5. Lakukan interaksi pada browser yang dibuka relay.
  6. Periksa tab Network, Console, dan Execution.
  7. Gunakan filter Network seperti Document, Script, Image, dan Preflight bila diperlukan.
  8. Klik Stop Capture, lalu periksa recording, evidence, dan history.
Manual Capture troubleshooting: jika browser tidak terbuka, cek instalasi browser dan profile lock. Jika log kosong, restart relay dan ulangi capture setelah CDP terhubung.

5. Katalon Capture Guide

  1. Pastikan project memiliki Keywords/com/utils/DevLog.groovy, Test Listeners/DevLogListener.groovy, dan Include/testcase-map.json.
  2. Pilih execution profile yang benar. Set webQaEnabled=true, webQaRelayUrl=http://127.0.0.1:3001/log, dan webQaRelayToken sama dengan QA_RELAY_TOKEN.
  3. Set webQaCaptureNetwork=true dan screenshot sesuai kebutuhan.
  4. Tambahkan mapping path test case Katalon ke internal QA-Web testCaseId.
  5. Jalankan QA-Web dan relay, lalu buka Devlog test case yang sudah dipetakan.
  6. Jalankan test case Katalon, misalnya QA WEB automation.
  7. Verifikasi run.started, step, network, console, dan run.finished.
CustomKeywords.'com.utils.DevLog.step'('Opening checkout page')
CustomKeywords.'com.utils.DevLog.network'('POST', checkoutUrl, checkoutResponse)
CustomKeywords.'com.utils.DevLog.console'('WARNING', 'Optional warning message')
CustomKeywords.'com.utils.DevLog.captureScreenshot'('checkout-result')

DevLogListener menangani start dan finish run secara otomatis. Jangan membuat runId baru untuk setiap step.

6. Katalon Test Case Mapping

Include/testcase-map.json menghubungkan path test case Katalon dengan internal database ID test case QA-Web.

{
    "Test Cases/QA Web automation": "00000000-0000-0000-0000-000000000001",
    "Test Cases/Checkout/Happy Path": "00000000-0000-0000-0000-000000000002"
}

Ganti placeholder dengan internal QA-Web testCaseId, bukan display ID seperti E-124. Jika mapping hilang, DevLog mengirim warning dan memakai ID bertanda unmapped:<katalon-path>, atau fallback sementara bila dikonfigurasi.

  1. Salin internal database ID dari detail test case QA-Web.
  2. Salin path lengkap test case Katalon, termasuk prefix Test Cases/.
  3. Tambahkan pasangan path dan ID, validasi JSON, lalu jalankan ulang test.
Jangan hardcode testCaseId pada script. Mapping membuat script reusable dan mencegah event masuk ke test case yang salah.

7. Event Contract

AutomationEventV1 adalah format bersama untuk Manual Capture dan Katalon Capture.

FieldArti
schemaVersion, eventId, runIdVersi kontrak, ID unik event, dan ID stabil untuk satu run.
mode, source, eventTypeMode capture, sumber event, dan jenis event.
testCaseId, testCaseNameIdentitas test case QA-Web dan nama/path test case.
message, timestampPesan dan waktu event.
url, method, responseStatusInformasi network.
cdpAvailable, fallbackUsedStatus CDP dan fallback capture.
screenshotPath, metadataLokasi screenshot dan informasi tambahan.

Event type umum: run.started, run.finished, step, console, network.request, network.response, screenshot, warning, dan error.

11. Best Practices

  • Selalu gunakan testcase-map.json dan jangan hardcode testCaseId.
  • Gunakan satu runId stabil per run.
  • Restart relay dengan sengaja sebelum validasi besar.
  • Biarkan Manual Capture dan Katalon Capture terpisah pada capture layer.
  • Jangan mengubah perilaku CDP relay tanpa menguji Manual Capture.
  • Jangan menghapus kompatibilitas /log sampai migrasi selesai.
